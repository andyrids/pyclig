# Plan - pyclig 1.0.0: API freeze

## Context

`develop` is at `663fcd8`: the v0.7.0 tree plus 8 lines in `docs/evaluation.md`. The tag is on
`main`, so `v0.7.0` is not an ancestor of `develop`. The next roadmap step is **"1.0 - API freeze"**
(`roadmap.md:71-73`): no new rows, and the public names, signatures and kit rule IDs of 0.7 are
frozen. No test locks the API today; only `test_paths.py:123` touches it, and the 0.6→0.7 signature
check was done by hand. This release makes the freeze enforceable, makes the one rename, and states
the stability promise.

Decisions taken with you:

- **One approved break:** `pyclig.options.confirm` is renamed `pyclig.options.confirm_name`.
  - No alias and no runtime guard.
  - The flag stays `--confirm NAME` and the parameter stays `confirmed`.
  - The pairs then read `confirm`/`force` and `confirm_name`/`confirm_name`. Today the mis-pairing
    `pyclig.confirm(force=confirmed)` skips the prompt without an error.
  - No consumer uses the factory.
  - `roadmap.md:14` ("never a breaking one") and its 1.0 section record this exception.
- **Kit stability: the policy now, the mechanism later.**
  - The 19 rule IDs are pinned by the API lock.
  - The README says any rule added after 1.0 is opt-in.
  - No `since=` and no scoped ignore keys yet (YAGNI).

Defaults you can override:

- **Exported:** `pyclig.Format`, `pyclig.Level` and `pyclig.Errors`.
  - They are the plain aliases `_run.py:50`, `_run.py:53` and `_output.py:40`.
  - Those modules are already on the `import pyclig` path, so nothing new is imported.
- **`ConfigError` stays internal.** It is in no public signature, and the runner prints it as `error:`
  with exit 1. Exporting it later would be additive.
- **`options.timeout` keyword order** becomes `(*, help, default, envvar)`, like
  `output`/`port`/`user`. Every parameter is keyword-only, so no call changes.
- **Declared internal, not renamed:** `Context(pyclig_state=)`, and the `Command.main(**extra)` keys
  `pyclig_consoles`, `pyclig_in_tty`, `pyclig_err_tty` and `pyclig_discover`.
- **FUT-1 stays `gap`/`out`.** It is about the application's interface; only its evidence changes.
- **The API lock is a committed text snapshot, `tests/api.txt`.** It is written first against the 0.7
  API, so every later item shows up as a deliberate diff of a few lines.

**Scope of authority:** local commits on `feat/api-freeze` from `origin/develop` only. Push, PR, tag,
release and filed issues each need a separate ask. Consumer repos are read-only and are tested as
fresh `git clone`s from their remotes, because the local pkgdx and template clones are stale. Files
marked immutable are proposed, not edited.

## Design

### Item 1 - API lock (`tests/test_api.py`, `tests/api.txt`)

Plain `str(inspect.signature())` differs across 3.11, 3.13 and 3.14 in three ways: the `IntEnum`
signature, `Union[A, B]` against `A | B`, and `pathlib._local.Path`. So the test renders signatures
itself, and that rendering was checked byte-identical on 3.11.16, 3.13.13 and 3.14.7.

**Each parameter is rendered as:** its name, the `*` marker, `*args`/`**kwargs`, `ann(annotation)` and
`repr(default)`. `ann` prints:

- a forward-reference `str` as its `repr`;
- `None`/`NoneType` as `None`, and a TypeVar as `~name`;
- lists and `...` item by item;
- a `Union` or `UnionType` as `A | B`, and a `Literal` as `Literal[...]`;
- another generic as its origin, then its arguments in brackets;
- a class as `module.qualname`, with builtins bare and `pathlib._local` mapped to `pathlib`.

**The file:** one sorted `key value` line per entry, under a `#` header that states the format and
the rules below. It covers:

- every `__all__` name of `pyclig`, `options`, `paths` and `testing`. `options` uses its public
  non-TypeVar names until Item 2 adds its `__all__`;
- type aliases, as `pyclig.Format = Literal[...]`, and submodules, as `... module`;
- each `ExitCode` member and its value;
- the public own-`__dict__` members of `Context`, `Command`, `Group`, `GlobalOption`, `Config` and
  `Finding`, properties included;
- `rule:<ID>` from the `Finding("ID"` regex already in `test_conformance.py:252-261`. That gives
  19 IDs, because BAS-5 has two rows.

**`test_public_api_is_frozen`** fails in three groups, and each lists the current line to copy:

- **removed:** "breaking - needs 2.0";
- **changed:** "breaking unless it only adds an optional parameter or reorders keyword-only ones";
- **added:** "add the line deliberately".

- **The `## Stability` section:**
  - **SemVer:** from 1.0, a breaking change needs 2.0.
  - **What is API:**
    - the names in the four `__all__` lists, their signatures, and the public class members;
    - `__version__`;
    - the `ExitCode` members and values, and the exit-code table;
    - stream discipline and the `ctx.format` values;
    - the run flags, and the flags and parameter names the factories add;
    - the `<PROG>_DEBUG`, `_NO_COLOR`, `_CONFIG`, `_PROFILE` and `_LOG_FILE` variables;
    - the config locations and precedence;
    - the kit rule IDs.
  - **What is not API:** help layout, message wording, styling, the bug-report URL body, the log
    format, `_` modules and names, and the `pyclig_*` keywords.
  - **Kit policy:**
    - the 1.0 IDs are never removed, renamed or split in 1.x;
    - a rule added after 1.0 is opt-in, so a bare `assert_conforms` that passes keeps passing;
    - the exception is a rule fixed to catch a case it missed, listed under `Fixed` with its ID.
  - **Support floors:**
    - Python >= 3.11, `click~=8.5` and `rich~=15.0`;
    - raising a floor or dropping an end-of-life Python is a minor release, listed under `Changed`;
    - a new click or rich major goes in a minor release only if the API holds; otherwise it is 2.0.
